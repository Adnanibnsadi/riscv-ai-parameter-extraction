# AI-Assisted Extraction of Architectural Parameters from RISC-V Specifications

An AI-assisted tool that extracts architectural parameters from RISC-V specification snippets and produces structured YAML output.

The project uses Google's Gemini 2.5 Flash model to identify parameters that are explicitly described as **implementation-specific**, **implementation-defined**, **optional**, or otherwise variable by implementation.

The extracted results are validated using **Pydantic** before being serialized to YAML.

## Features

* AI-assisted extraction of architectural parameters
* Gemini 2.5 Flash integration
* Structured JSON responses
* Pydantic schema validation
* Response normalization for minor LLM formatting inconsistencies
* YAML output generation
* Evidence and constraints for extracted parameters
* Automated tests using pytest
* Protection against unsupported inference and hallucination through prompt constraints

## Extraction Pipeline

```text
RISC-V Specification Snippet
            |
            v
      Gemini 2.5 Flash
            |
            v
       JSON Response
            |
            v
   Response Normalization
            |
            v
    Pydantic Validation
            |
            v
        YAML Output
```

## LLM Details

* **Provider:** Google
* **Model:** Gemini 2.5 Flash
* **SDK:** Google GenAI Python SDK
* **Temperature:** 0
* **Response format:** JSON
* **Validation:** Pydantic

## Installation

Clone the repository and create a virtual environment:

```bash
git clone https://github.com/Adnanibnsadi/riscv-ai-parameter-extraction.git
cd riscv-ai-parameter-extraction

python -m venv .venv
```

Activate the virtual environment on Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

Install dependencies:

```bash
pip install -r requirements.txt
```

## Configuration

Create a `.env` file in the project root:

```text
GEMINI_API_KEY=your_api_key_here
```

The `.env` file is excluded from Git using `.gitignore`.

## Running the Extractor

Place RISC-V specification snippets as `.txt` files inside:

```text
data/
```

Run:

```bash
python src/extractor.py
```

The extractor processes all `.txt` files in the `data` directory and writes the corresponding YAML results to:

```text
output/
```

For example:

```text
data/snippet_1.txt
```

produces:

```text
output/snippet_1.yaml
```

Existing output files with the same filename are overwritten.

## Results

The `results/` directory contains the final YAML outputs generated by the extraction pipeline for the two RISC-V specification snippets provided in the coding challenge.

- `results/snippet_1.yaml` — Extracts three implementation-specific cache parameters:
  - `cache_capacity`
  - `cache_organization`
  - `cache_block_size`

- `results/snippet_2.yaml` — Returns an empty parameter list because the snippet describes fixed CSR address-mapping conventions rather than implementation-variable parameters.

## Testing

Run the complete test suite with:

```bash
python -m pytest -q
```

The current test suite contains **16 tests** covering:

* Pydantic validation
* Required fields
* Empty extraction results
* Evidence normalization
* Confidence validation
* Mocked Gemini responses
* Invalid JSON handling
* Empty API responses
* API error handling
* YAML output validation

## Limitations

The current implementation is a prototype that processes individual text snippets. A larger-scale implementation would require complete RISC-V document ingestion, automatic document chunking, source location tracking, duplicate detection, and evaluation against a manually annotated dataset.
